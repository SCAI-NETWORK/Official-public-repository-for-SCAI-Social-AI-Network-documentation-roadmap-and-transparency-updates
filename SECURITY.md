# Security Policy

SCAI Social AI Network is designed as a non-custodial intelligence and automation ecosystem. Users remain responsible for their own wallets, exchange accounts, API permissions and private credentials.

## Security Principles

- SCAI should never ask users for seed phrases or private keys through public forms.
- API keys and signers must be user-specific and permission-scoped.
- Exchange credentials should be configured with withdrawals disabled where possible.
- Sensitive settings should be masked after saving.
- Platform operations should be auditable through logs, ledgers and exports.
- Live execution should be gated by user approval, profile limits and safety checks.

## Responsible Disclosure

If you believe you have found a security issue, contact:

**support@scainetwork.com**

Please include:

- A short summary.
- Impact description.
- Reproduction steps if safe to share.
- Affected page, contract, feature or workflow.
- Wallet address only if required for context.

Do not include:

- Seed phrases.
- Private keys.
- API secrets.
- Passwords.
- 2FA codes.
- Any third-party private data.

## Current Scope

Publicly visible scope includes:

- Website pages.
- Public documentation.
- Public support forms.
- Published smart-contract references.
- Public investor dashboard behavior.

Private bot internals, execution infrastructure and platform credentials are not part of public testing without explicit authorization.
